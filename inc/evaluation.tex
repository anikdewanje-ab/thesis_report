results, and Chapter~\ref{ch:critique} examines the design itself.

\section{Study Design}
\label{sec:eval:overview}

We compare two coordination systems on the same evacuation task. The
\emph{treatment} is the database-centric agentic system of
Chapter~\ref{ch:agentic}. The \emph{control} is the workflow baseline of
Chapter~\ref{ch:workflow}, a single scripted Incident Commander. The main
independent variable is the coordination architecture at the command post. The
baseline also simulates the execution of orders, while the agentic side runs
its field agents live (deviation~7 below).

\paragraph{Parity.} Apart from this, everything is held constant, mostly by
reusing code.
The baseline engine is a subclass of the agentic engine, and 27 of its
attributes are the same function objects the live agents use. An executable
conformance test checks parity on five axes: information horizon, action
vocabulary, world model, scenario inputs and output substrate. Seven known
deviations remain, and Table~\ref{tab:eval:deviations} lists each with its
direction. Four only label or address the records and cannot change a
score. Two favour the baseline, and one works in both directions.

\begin{table}[htbp]
\centering
\caption[The seven parity deviations]{The seven known deviations between the
two conditions, with the direction of each.}
\label{tab:eval:deviations}
\small
\begin{tabularx}{\textwidth}{c>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}p{3.6cm}}
\toprule
\# & Deviation & Effect on a result \\
\midrule
1 & A baseline message's id is its position in the run, not a clock time, so two runs of one scenario are identical. & None. No code reads it. \\
2 & A baseline message names its receiver, because the offline walk has no dispatcher. & None. No code reads it. \\

\paragraph{Pairing.} Paired runs use matched scenario
files, read by the same loader, and write to the same append-only
\code{event_log}. The files are not byte-identical. The baseline files declare
a world (deviation~7), except the road-closure file. That file declares no
world, and its drop-offs come from the script, so the baseline's road-closure
score does not depend on its orders (Section~\ref{sec:crit:gate0}). In the
same file one school cannot be reached and only 60 residents are declared, so
its ceiling is 60 in place of 100
(Section~\ref{sec:cs:disruptions}). The road-closure cells are therefore not
like-for-like (Section~\ref{sec:res:anticipated}). The simulator has no model of resident behaviour, sensors or
message latency, so only the policy varies between runs. Its seed is derived
from the scenario, the time scale and the replicate index, never from the
model, so the agentic runs of one replicate draw the same seed, a design known
as common random numbers. The baseline is deterministic and ignores the seed,
so each paired difference compares an agentic run with a fixed reference. Seeded model calls are still only
near-deterministic (Section~\ref{sec:data:replay}), so every cell is
replicated.

\paragraph{Unit of analysis.} The unit is the run. Each cell of system,
scenario, model and time scale is repeated $k = 10$ times. The
variance on the agentic side is reported in full as a cost of the
architecture.

\paragraph{Models.} The design called for at least three language models
across a range of capability, to test whether an advantage holds across models
(H3). Three models completed the novel arm at 50 runs each: glm-5.2,
deepseek-v4-pro and qwen3.5. The first two were fixed before the arm ran. The
third slot changed after data were seen, which departs from the registered
selection rule (Amendments~5 and 10 to~12, Table~\ref{tab:eval:amendments}),
so the novel arm's model set is exploratory. Partial series
(Section~\ref{sec:res:summary}) are never pooled and are compared on $S$ only.
Hosted \texttt{:cloud} model tags cannot be frozen to a version, and inference
is not bit-exact even with a fixed seed \parencite{yuan2025}, so drift is
logged on every run but cannot be prevented. A failed or malformed model call is never retried and
counts as a hard failure. A retry would give a weak model a second attempt that
a strong model never needed.

\paragraph{Harness.}
\label{sec:eval:harness}
One harness runs every cell. For each run it writes a manifest row into the
append-only log: system, model and digest, scenario and hash, time scale,
replicate, policy seed, git commit and whether the working tree was clean,
threshold hash, and platform. A run's provenance can therefore be recovered
from the log. Agent state and the route cache sit at fixed paths, so the sweep
is serial. An agentic run on the anticipated arm took about 20 wall-minutes,
and any drift in the hosted models is confounded with a run's position in the
sweep.

\paragraph{Headless world client.} On the agentic side, a bus leg closes only
when the world acknowledges that the task is complete. In the first pilot only
the browser's vehicle animation sent that acknowledgement, so without a browser
no bus arrived and every agentic cell scored level 0. We ruled that pilot
invalid and re-ran it. Every agentic cell instead runs a headless client that plays
the animations from the backend's own events, and refuses to start while a
browser tab is connected, since both would acknowledge every leg.

\section{Hypotheses}
\label{sec:eval:hypotheses}

We registered four hypotheses before any evaluation run
(Table~\ref{tab:eval:hypotheses}). H1 and H2 are confirmatory and together
answer RQ1. H3 and H4 are estimation questions without a significance test.

\begin{table}[htbp]
\centering
\caption{The registered hypotheses.}
\label{tab:eval:hypotheses}
\small
\begin{tabularx}{\textwidth}{l>{\raggedright\arraybackslash}Xll}
\toprule
 & Hypothesis & Arm & Form \\
\midrule
H1 & The agentic system is not worse than the baseline on survival, on disruptions the baseline has a written branch for. & Anticipated & Non-inferiority, $\delta_{NI} = 0.05$ \\
H2 & The agentic system is better than the baseline on disruptions the baseline could not have encoded. & Novel & Superiority, $\delta_m = 1$ level \\
H3 & An H2 advantage holds across a range of models, with a capability threshold below which it disappears. & Both & Estimation \\
H4 & There is a time scale at which the agentic system's thinking time starts to cost more than its coordination gains. & Both & Estimation \\
\bottomrule
\end{tabularx}
\end{table}

The registered claim needs both H1 and H2. Section~\ref{sec:eval:analysis} gives the decision rule for each
scenario. The pre-registration adds a sign test across scenarios with
Holm--Bonferroni correction, but it fixes no rule for combining the verdicts of
several models into one verdict on a hypothesis. We therefore report every cell
and state for each hypothesis how many of its confirmatory cells pass
(Section~\ref{sec:res:anticipated} and Section~\ref{sec:res:novel}). If
both systems collapse to level 0 or 1 across the novel set, the campaign is in
the \emph{null zone} and is reported as uninformative rather than as a tie.

The design assumed, without testing it, that the scenarios demanded a change
of plan (Section~\ref{sec:crit:gate0}).

\section{Scenarios and the Disruption Firewall}
\label{sec:eval:scenarios}
\label{sec:eval:firewall}

The suite has two anticipated scenarios and five novel ones.
Section~\ref{sec:cs:disruptions} describes each disruption, and
Appendix~\ref{app:scenarios} prints each disruption message word for word.

The baseline has a written branch for the anticipated disruption, the road
closure, and both anticipated scenarios were visible during development. Two scenarios are a thin base for a
per-scenario analysis, and we count this as a limitation. A third, a shelter
closure, had no agentic counterpart, because the live shelter agent has no
handler that lowers its beds. We excluded it from scoring on 2026-09-10 and
kept it as the fixture for the negative control
(Section~\ref{sec:eval:noreplan}).

Our company supervisor, the domain expert Rüdiger Höfert,
wrote them blind to the baseline. The brief named only the kind of disruption we wanted:
compound, involving several actors, and unfolding during the mission. Their
identifiers \code{novel_1} to \code{novel_5} were reserved before their content
existed, and every supplied scenario had to be run, however hard, badly formed
or unfavourable. The baseline was frozen and tagged in git on the morning of
2026-09-10 (Section~\ref{sec:eval:availability}), and the five scenarios were
saved that afternoon, so the baseline could not have encoded them. One later
change to baseline code added the switch for the negative control. Amendment~6 discloses it with evidence that
the doctrine's behaviour did not change.

Blind supply carries the risk of the null zone, since a disruption may land too
easy or too hard with no time to replace it. The brief was the only
mitigation, and we decided against a behavioural pilot on self-written
disruptions. A scaling sweep over resident count, shelter topology and fleet
size was registered as exploratory and was not run, so the evidence rests on a
single case study.

\section{Measuring Survival}
\label{sec:eval:primary}

The primary outcome is the Recovery-Outcome Level, an ordinal scale from 0 to 4.
It is built from the survival rate $S$, which is the co-primary outcome for
safety. One frozen function of the event log computes both.

\subsection{Feasibility Ceiling}
\label{sec:eval:ceiling}

Some disruptions leave fewer residents savable, so we normalise the outcome by
the feasibility ceiling
\begin{equation}
N =
\begin{cases}
\min\!\left(P,\ \sum_s b_s\right) & \text{if } \sum_s b_s > 0,\\[2pt]
P & \text{if no shelter declared any capacity,}
\end{cases}
\label{eq:eval:ceiling}
\end{equation}
where $P$ is the declared population and $b_s$ the beds shelter $s$ declared.
The fallback to $P$ stops a total of zero from making every run trivially
complete. The ceiling comes only from what the scenario and the shelters
declared. If it depended on what a run did, a system could lower its own
denominator and score better by doing worse.

\subsection{Survival Rate and Loss Decomposition}
\label{sec:eval:survival}

A resident is lost in one of three ways: \emph{never delivered} to any
shelter, set down \emph{late} after the flood arrival, or \emph{refused} at a
shelter that was closed or full. An arrival counts only if it was set down by
the flood arrival of its zone. Each shelter then admits the in-time arrivals in
time order up to its declared beds, and only the residents above that limit are
invalidated. So a run that saved everyone with one flaw cannot rank below one
that cleanly saved a third of the home. The residents who pass both filters are
the validly sheltered residents $V$, and
\begin{equation}
S = \frac{V}{N}, \qquad
N = \underbrace{(N - H)}_{\text{never delivered}} + \underbrace{M}_{\text{late}} + \underbrace{O}_{\text{refused}} + \underbrace{V}_{\text{safe}},
\label{eq:eval:survival}
\end{equation}
where $H$ is the number reported sheltered, $M$ the number set down late, and
$O$ the number refused for want of a bed. $S$ alone cannot tell a slow
coordinator from one that drove residents somewhere lethal, so we always
publish the decomposition beside it.

The arrivals come from different places in the two systems. In the agentic
system, an arrival is a bus driver's drop-off report. It carries the headcount
that the driver, a language model, writes into it. The scripted shelter agent
answers with an intake message that repeats this headcount, up to its free
beds. The scorer counts the pair once, keyed by shelter and mission. Nothing
checks the headcount against the residents who boarded. In the baseline, the
execution model writes the drop-off from the IC's committed order when the bus
reaches the shelter (Section~\ref{sec:wf:world}). The scorer is deterministic
in both systems, but on the agentic side its input is partly what the agents
report. Section~\ref{sec:res:integrity:ceiling} and
Table~\ref{tab:crit:limits} take up what this means for the results.

\subsection{Recovery-Outcome Level}
\label{sec:eval:rubric}

Each run is placed on a five-level ladder with one axis, valid completeness
$C = S$. Bus-kilometres $K$ only split the top two levels:
\begin{equation}
L(C, K) =
\begin{cases}
0 & C < 0.10 \quad \text{collapse}\\
1 & 0.10 \leq C < 0.50 \quad \text{major loss}\\
2 & 0.50 \leq C < 1.00 \quad \text{partial}\\
3 & C = 1.00 \ \wedge\ K > 1.25\,K^\ast \quad \text{complete, degraded}\\
4 & C = 1.00 \ \wedge\ K \leq 1.25\,K^\ast \quad \text{complete and efficient}
\end{cases}
\label{eq:eval:ladder}
\end{equation}

We wrote down a reason for each cut before any result existed. The cut at 0.50
is half the home, the line between a mass-casualty event and an incomplete but
largely successful operation. The cut at 0.10 is one part-load of a single
50-seat bus, so a run below it never started an evacuation. The
25\,\% band at the top leaves room for a legitimate detour or second pickup.

$K^\ast$ is the median bus-kilometres of the control runs in the same cell that
delivered everyone, and it needs at least three such runs. Without $K^\ast$, no
run may rise above level 3. The comparison stays within one system and asks
whether it drove further than it needed to. Level 4 is the one place where the
ladder mixes safety with efficiency, so the protocol defines it as passing both
Gate 1 and Gate 2 (Section~\ref{sec:eval:gates}).

A pass/fail outcome would throw away the difference between losing one
resident and losing fifty. Stroke trials keep the ordinal modified Rankin Scale
for the same reason
\parencite{ganesh2018},
though they disagree about where a single cut should fall
\parencite{nunn2016}. We borrow only the shape of the scale, with no claim of
clinical comparability.

\subsection{Deterministic Scorer}
\label{sec:eval:scorer}

No human scores anything. One frozen function of the event log
(Section~\ref{sec:data:evalbackbone}) computes every outcome for both systems.
We do not use a language model as a judge, as is common \parencite{zheng2023}
and as some agent benchmarks do \parencite{xu2025}, because a model judging
models would bring back the nondeterminism we are trying to measure. A missing
value is never a zero. Every interpretive constant lives in one data-only
threshold file, whose hash is written into every run's manifest.

\section{The Three Gates}
\label{sec:eval:gates}

A combined score lets a system trade safety for speed. The protocol therefore
reads three gates in a fixed order, and a gate is read only if every gate above
it passed (Figure~\ref{fig:eval:gates}). The reference protocol has a fourth
gate, equity, which we register as undefined
(Section~\ref{sec:eval:metrics}).

\input{pics/method-gates}

\subsection{Gate 1: Safety}
\label{sec:eval:gate1}

Gate 1 asks whether the residents survived. Its effect measure is the paired
risk difference per scenario, treatment minus control,
\begin{equation}
\widehat{RD} = \frac{1}{n}\sum_{i=1}^{n} \big(S_{A,i} - S_{B,i}\big),
\label{eq:eval:rd}
\end{equation}
over the $n$ matched pairs, with a bootstrap interval and a Wilcoxon check
(Section~\ref{sec:eval:analysis}). On the anticipated arm the gate passes when
$\widehat{RD} > -\delta_{NI}$. On the novel arm it passes when
$\widehat{RD} > 0$ and the paired interval excludes zero. Without a registered
margin the verdict is \texttt{unregistered}, which counts as a failure. A
condition that fails Gate 1 is reported as a failure, and its Gate 2 and Gate 3
figures are not published as achievements.

We take the non-inferiority margin from clinical trials \parencite{piaggio2012}.
$\delta_{NI} = 0.05$ is five residents out of 100, half the 0.10 part-load that
is the smallest unit the ladder knows. We chose a strict margin because a wide
one makes matching easy to show and worthless to claim. The H2 margin
$\delta_m$ is one whole level and is read on levels, never on $RD$.

\subsection{Gate 2: Speed and Flow}
\label{sec:eval:gate2}

Gate 2 asks how quickly the residents reached safety. Its main measures are
clearance times at $q \in \{0.50, 0.90, 0.95, 1.00\}$. With the admitted
arrivals in time order and $F(j)$ their running count,
\begin{equation}
T_q = \min\big\{\, t_j \ :\ F(j) \geq \lceil q\,N \rceil \,\big\}.
\label{eq:eval:tq}
\end{equation}
The quantile is a share of the ceiling $N$, and not of the residents a run
happened to save. If survival is below $q$, then $T_q$ is censored and never
imputed. Otherwise a system that saved the easy half and stopped would post an
excellent $T_{90}$. A cell's clearance times are taken over its runs that
saved everyone, and they are read only in a cell that passes Gate~1. Gate 2 is
descriptive. We registered one expectation for it, that the baseline would win
on latency and cost.

\subsection{Gate 3: Adaptability}
\label{sec:eval:gate3}

Gate 3 asks whether an advantage survives disruptions nobody planned for. The
baseline must pass 100\,\% of the anticipated set, which all 20 campaign
baseline runs did with $S = 1.0$, on the road closure against its reduced
ceiling of 60 (Section~\ref{sec:res:anticipated}). On the novel set, the per-scenario level
distributions are compared by first-order stochastic dominance, which is part
of the H2 rule (Section~\ref{sec:eval:analysis}). A degradation curve over \code{SIM_TIME_SCALE} was to show where an
advantage vanishes. Only one scale, 8.4, was executed, so H4 was not tested
(Section~\ref{sec:res:h4}).

\subsection{The No-Replan Control}
\label{sec:eval:noreplan}

A third condition runs beside the two under test: the doctrine baseline with
re-planning switched off. Its first committed plan is its only plan, and the
rest of the doctrine is unchanged. This one ablation separates re-planning from
reasoning about what to re-plan. It is also the instrument's negative control
\parencite{lipsitch2010}, under a rule registered as a gate on the whole
campaign:

\begin{quote}
Before any result is claimed, the no-replan control must score strictly below
the doctrine baseline on at least one disruption.
\end{quote}

We read the gate on the
shelter-closure fixture, where a re-plan changes who is delivered. It passed on
2026-09-14, with the doctrine at level 3 and $S = 1.0$ and the control at
level 0 and $S = 0.0$. The protocol did not read it on the scored scenarios,
where the control ``cannot differ from the doctrine in outcome, by
construction'' (Section~\ref{sec:crit:gate0}).

\section{Secondary Measures}
\label{sec:eval:secondary}

\subsection{Held-Out Decision Rubric}
\label{sec:eval:heldout}

Four of the five novel scenarios state that their main effect is ``judged
mainly on the decision rubric''. The simulator models no patient (S04), no
staircase or police officer (S06), no payload cap (S07) and no partly damaged
shelter (S08), so a coordinator that ignores the report can still reach a full
level. S05 contains an explicit checklist. We settled the rubric on 2026-09-11,
before any novel-arm data, and Amendment~6 registered it as the novel arm's
secondary outcome.

The rubric is descriptive and never merged with $L$. Each criterion reads only
the structure of the log: who was addressed and when, what the orders booked,
and what was set down where. It never reads message text, because keyword rules
would be brittle across models. We report yes, no and unanswerable counts per
criterion, and an unanswerable criterion never counts as a failure.
Table~\ref{tab:eval:heldout} condenses the 16 criteria.

\midrule

S05 & The report is verified with police or ZKD before it is retracted. The standing runs land as ordered. The reserve bus is committed as a hedge by 10:57. Nothing new is still moving after the retraction. \\

Before any held-out run we recorded what the baseline would do. The doctrine
answers every held-out report with the same hold, status messages to ZKD, the
transport operator and the home, and no new order. It therefore passes the
informing criteria by construction and fails those that need a changed plan.
The rubric shows where the conditions differ, but gives H2 no effect size.

\subsection{Other Metrics}
\label{sec:eval:metrics}

Each run also records measures that cannot move the level: bus-kilometres $K$,
resource efficiency $\eta = V / K$, wall latency and tokens, capacity
overloads, constraint violations, and the time of the last counted drop-off.
Bus-km is composed differently in the two
systems, so the code refuses to compare it across systems. Leg and supersede
counts are diagnostics only, since a supersede count used as a score would
reward churn. Table~\ref{tab:app:secondary} gives bus-km, $\eta$ and the
rejected messages per cell. Equity is undefined. Residents are counted as integers with no
attribute to split on, so the ladder cannot tell a run that sheltered the 60
most mobile residents from one that sheltered the 60 least mobile
(Section~\ref{sec:crit:limitations}).

\subsection{Response-Time Cost}
\label{sec:eval:responsetime}

Model calls take time. We report the wall-clock latency $\lambda$ of the model
calls per model, and the operational delay in simulated time
$\Delta_{\text{op}} = \lambda \cdot \sigma$, where $\sigma$ is the time scale.
The delay is given as a share of the disruption's decision budget,
$\phi = \Delta_{\text{op}} / (D_z - t_{\text{first event}})$, where $D_z$ is
the flood arrival in the zone (12:00), because the same
delay can be harmless under a slow disruption and fatal under a tight one.
$\lambda$ is summed over all ten agents, which think in parallel, so
$\Delta_{\text{op}}$ is an upper bound. The primary outcome leaves latency and
cost out on purpose, since operational cost is not the outcome that matters in
a disaster \parencite{holguin-veras2013}.

\subsection{Exploratory Process Measures}
\label{sec:eval:v2}

Section~\ref{sec:res:loss} and Chapter~\ref{ch:critique} use process measures
that Protocol~v2 added after the data had been seen (Amendment~16). They are
exploratory, and none of them enters a gate.

\paragraph{Loss attribution.} The deficit $1 - S$ is split into the three
channels of Equation~\ref{eq:eval:survival}: residents never delivered
($N - H$), set down late ($M$) and refused for want of a bed ($O$). The
never-delivered count is floored at zero, so a run that reports more arrivals
than the ceiling cannot push it below zero (Section~\ref{sec:res:integrity}).

\paragraph{Handshake closure.} An addressed request is a message to one named
agent whose type expects a reply, for example a capacity query to a shelter or a
mission order to a driver. Closure is the share of addressed requests that have a matching
reply from that agent. The pairs of request and reply types were set from the
49 message types found in the log. Reports that expect no answer, such as a
position update, are left out. Each agent stamps rows with its own clock, so the
log cannot put two agents' rows in order. Requests and replies are therefore
matched as pairs regardless of order, and no reply time is measured. Closure
asks whether an answer came back, not whether it was right. The baseline has a
single coordinator with no peers and sends no addressed requests, so it has no
closure figure.

\paragraph{Plan revisions.} A plan revision is a message that sets or changes
the bus plan. We count two types in the event log: BIS's \code{dispatch_buses}
request to Hochbahn, and Hochbahn's \code{transport_plan}, which it sends to
BIS each time its run schedule changes. The first plan counts, and so does a
small change such as a firmer arrival time. A mission needs at least one
message of each type, so two is the floor, and every run reached it. Beside
this count we record each run's aborts, and classify the stated reason of each
abort as a response to a failure, a re-plan, or other.

\paragraph{How the diagnostic was chosen.} We chose which process measure to
report after seeing the data. Besides plan revisions we examined the number of
aborts, the number of missions dispatched, the three loss channels and the
candidate causes in Table~\ref{tab:disc:ruledout}. Among the measures that are
not part of the definition of $S$, plan revisions had the strongest
association with $S$. Their correlation describes these runs only and, as the
largest of several, overstates the association.

\section{Statistical Analysis}
\label{sec:eval:analysis}

\paragraph{Stochastic dominance.} The levels are ranked but not evenly
spaced, so a mean level has no meaning. Where a continuous quantity is needed
we use $S$, which is why $RD$ can be a mean. Level distributions are compared
by first-order stochastic dominance, which needs no arithmetic on an ordinal
scale \parencite{yalonetzky2013}. With
$\hat p_{\mathcal A}(L)$ the share of runs in sample $\mathcal A$ above level
$L$,
\begin{equation}
\mathcal A \succ \mathcal B \iff
\big(\exists L : \hat p_{\mathcal A}(L) > \hat p_{\mathcal B}(L)\big)
\wedge
\big(\nexists L : \hat p_{\mathcal B}(L) > \hat p_{\mathcal A}(L)\big).
\label{eq:eval:dominance}
\end{equation}
If the distributions cross, neither dominates. With $k = 10$ and five levels
some cells are nearly empty, so we print the raw level counts of every cell
(Table~\ref{tab:app:levels}).

\paragraph{Intervals and the paired check.} Every risk difference carries a
95\,\% percentile bootstrap interval \parencite{efron1979} from 10\,000
resamples of the paired differences at the fixed seed 20260904. A Wilcoxon
signed-rank test \parencite{wilcoxon1945} on the same differences is an
assumption-light check. Zero differences are dropped from the test but
counted, because pairs that mostly tie say something about the systems.

\paragraph{The H1 rule.} H1 passes on a scenario when
$\widehat{RD} > -\delta_{NI}$, a rule on the point estimate with no
significance level. The pre-registration first named a one-sided test on the
interval's lower bound. On 2026-09-12, with pilot data seen, we registered the
rule the code had always used and left the margin unchanged. A system at the
margin therefore passes about half the time at any $k$. We report a pass as
``the point estimate lies inside the margin'' and never as ``non-inferiority
demonstrated''.

\paragraph{The H2 rule.} The pre-registration names one primary test for H2
and two conditions beside it. The primary test is an exact Clopper--Pearson
interval \parencite{clopper1934} on
$P(\text{level}_{\text{agentic}} \geq \text{level}_{\text{baseline}})$ over the
$k$ agentic runs, aggregated across scenarios by a sign test with a
Holm--Bonferroni correction \parencite{holm1979}. We implemented it only after
the novel-arm data had been seen (Amendment~15), so it is exploratory
(Section~\ref{sec:crit:power}). The H2 verdict therefore rests on the two
conditions, which we call its co-primaries. The first is Gate~1 on survival.
The second is a minimum effect on the level scale, because passing Gate~1 does
not yet support a claim to have won. It needs both
\begin{equation}
\operatorname{median}\big\{L_{A,i} - L_{B,i}\big\} \geq \delta_m = 1
\quad\wedge\quad
\mathcal L_A \succ \mathcal L_B.
\label{eq:eval:h2}
\end{equation}
Dominance is included because a median can hide a bad tail. Four runs at level
4 and two at level 0 give a median shift of two levels from a system that
abandoned the home in a third of its runs, and the rule rejects this. H2
passes on a scenario only if both co-primaries pass.

\paragraph{Multiplicity.} H1 and H2 are claims on two disjoint scenario sets,
each with one primary outcome, so no correction is applied between them. Within
an arm the correction is Holm--Bonferroni. Runs are never pooled across
scenarios, which differ in ceiling, fleet and deadline. Secondary outcomes are
descriptive and not corrected.

\paragraph{Choosing $k$.} We sized $k$ on a pilot of 22 paired cells on the
anticipated set. No cell reached the target H1 pass rate of 0.80 at any $k$
from 3 to 200, because every pilot mean already lay below $-\delta_{NI}$. The
margin could not be widened, so we set $k = 10$ on budget and precision grounds
and recorded that H1 was not expected to pass (Amendment~1).

\paragraph{Exclusions.} A run can be excluded only for a simulator or harness
crash, a harness timeout, or right-censoring. A run is right-censored when it
stopped before $D_z$ plus 900 simulated seconds, about one shuttle turnaround,
so that a late drop-off could still have been missed. An unfavourable outcome,
an outlying latency or a hard novel scenario is never a reason. The event log
is append-only by database trigger, so removing a run would leave a trace.

\paragraph{Cut-point sensitivity.}
\label{sec:eval:sensitivity}
A threshold-based outcome invites the charge that the thresholds were chosen to
produce the result. Every score therefore also carries its level at the
level-1/2 cuts 0.40, 0.50 and 0.60, and we report the headline together with
this table (Section~\ref{sec:res:sensitivity} and
Table~\ref{tab:app:levels}). It is a small specification curve
\parencite{simonsohn2020}. The 0.10 and 1.00 cuts are
anchored, so we sweep only the half-home cut.

\section{Pre-Registration and Amendments}

hypotheses written after the results misrepresent what was tested
\parencite{gelman2014}. Pre-registration guards against both
